The LobangKaki experience is a client-only, in-memory festival simulator; no deal or volunteer attestation persists or reaches a real resident, because the project intentionally has no connected backend.
Meal tips from chat are never spoken as verified offers; only a live-camera/location-checked listing can enter the demo volunteer check, because seniors must not be sent to phantom deals.
The in-app README imports the project README directly; preserve all supplied sections while updating the renamed identity and documenting new features, so judges see the current app documentation.
Meal deal expiry uses a short client-side deadline and a periodic wall-clock check, so stale verified audio is withdrawn even after a suspended tab resumes.
Pitch slide navigation stores its index in the URL search parameter, so a slide can be linked and refreshed without a duplicate routing structure.
The supplied pitch is authored as eleven browser-native slide views rather than embedding PDF pages, so it remains navigable and readable as HTML; demo-only claims stay qualified.
Keep quick actions immediately before the chat transcript and project/competition information after the experience, so residents reach the core task first.

Resident language uses a shared locale-copy module for speech locale and key safety responses; device/browser availability is not guaranteed, and the Hokkien label falls back to Mandarin. Meal dietary filtering only uses explicit poster declarations, never text guesses, to avoid unsafe eligibility claims.

- Desktop presentation uses a viewport-height phone frame instead of page-level CSS zoom, preventing clipping while preserving mobile proportions.
